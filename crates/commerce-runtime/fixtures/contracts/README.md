# Contract fixtures

**These are engine tests, not a contract registry.** Nothing is seeded from
this directory and no migration reads it. Adding an endpoint needs nothing
here — contracts are rows, generated by `scripts/harvest-contracts.mjs` from
evidence the database already holds.

There are two kinds of file, and five of each. Five, not 2607, and that is the
point: they exist to test the extraction ENGINE against real data, the way you
need two or three real inputs to test a parser.

- `payloads/*.json` — **real production response bodies**, copied verbatim out
  of `call_runs` rows that returned HTTP 200. No provider was called to produce
  them and none is called to use them.
- the rest — a contract per payload, so the engine has something to run.

| payload | run | what it proves |
| --- | --- | --- |
| `kvk-zoeken-volve-capital.json` | `087c59d1` | two rows, one company: the same `kvkNummer` as `hoofdvestiging` and as `rechtspersoon`. Collapsing on identity is not optional. |
| `kvk-zoeken-mollie-bv.json` | `23b2198f` | ten distinct companies for one name. This is what a real ambiguity looks like. |
| `kvk-basisprofiel-mollie.json` | `d2d57ff5` | the profile shape, including `_embedded` and the address array. |
| `kvk-jaarrekening-86717162.json` | `3f9b64bf` | filed figures returned INLINE — no second document fetch — and a balance sheet with no income statement, which is why revenue is optional. |
| `pdok-locatieserver-bellamyplein.json` | `f5392262` | `numFound: 523624` with ten docs returned, and a house number that only `huis_nlt` carries. |

They are used twice:

1. `gateway/src/facts/contract.rs` runs the extraction engine over them, so a
   change to path parsing, cardinality or an adapter fails `cargo test` rather
   than a paid job.
2. `scripts/harvest-contracts.test.mjs` runs the INFERENCE over the same
   payloads and asserts it derives these contracts from the `fact_types` rows
   alone — which is the proof that the harvester replaces hand-writing them.

When a provider changes shape, replace the payload with a new real body and
record which run it came from. Do not hand-edit one to make a test pass.
