Earlier implementation and local validation

The reference request is: “Can you look up Mollie B.V. by name and combine
its registered details, available annual financial figures and website
information?” English and Dutch variants keep the complete three-part scope.
The existing source graph searches the register, resolves or explicitly selects
the company, obtains its profile and available financial figures, then uses
the selected register identity for website research. It does not guess a domain.

Changes in this patch

* Common English/Dutch wording shares the checked source plan. Additional years,
  latest-filing requirements, DNS, extra entities or output formats are not
  silently discarded by the literal path; they retain the normal full parser.
* The App displays the gateway's scope limitations before purchase approval.
  MCP avoids attributing the API billing currency to filing figures, preserves
  RSIN/date identifiers, and does not switch English headings to Dutch merely
  because a registry quotation is Dutch.
* Eight exact-name DNS lookups: A, AAAA, CNAME, MX, NS, TXT, CAA and SOA. Each is
  one upstream query; subdomains and underscore labels remain intact. Answers
  retain record type, name, original value, TTL (or null), response status,
  DNSSEC indicator, source URL and truncation coverage. Unsupported types and
  mismatched provider questions are rejected. DNS does not prove legal ownership,
  service availability or a complete zone inventory.
* DNS search preserves the requested record type. RDAP and legacy MX cannot
  silently substitute for another type. Record types explicitly excluded in
  a description are not added to the request. A mixed old/new catalog test
  verifies that exact-record and subdomain queries cannot select legacy MX,
  whose adapter strips subdomains; ordinary root-domain mail checks still work.
* The resolver compares complete buyer cost including prerequisites, then chooses
  fewer calls when total prices tie. It does not prefer a source because it uses
  x402. New DNS entries inherit the existing MX tariff rather than inventing one.
* External discovery distinguishes the configured direct-fetch estimate from
  the standard balance-purchase estimate. Neither is an executable purchase
  authorization; the live input contract, network and price must pass admission.
